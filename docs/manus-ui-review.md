# مراجعة تجريبية للواجهة الرئيسية

## النطاق والضمانات

هذه التجربة تطوير بصري للصفحة الرئيسية العربية الموجودة، وليست مشروعًا بديلًا. تبقى الألعاب والقصص والحلقات والأصول والروابط وبيانات التقدم ومحركات الألعاب كما هي. أُعدّت للمراجعة أولًا، ثم أذن صاحب المشروع بنشرها؛ ولا تغيّر إعدادات النشر أو فروع إصدارات التطبيق. لا يلزم أي إطار عمل أو حساب أو خدمة جديدة لتشغيلها أو مواصلة تطويرها باستخدام Git وChatGPT وCodex.

## نتائج الفحص

- الموقع ثابت وثنائي اللغة: الرئيسية في `index.html` ونظيرتها الإنجليزية في `en/index.html`؛ ملفات التصميم والسلوك المشتركة في `assets/`.
- تضم صفحات الألعاب العربية 20 لعبة و306 مستويات و1,669 جولة؛ بيانات المستويات موجودة في صفحات الألعاب نفسها، والتقدم والاستئناف في `assets/game-progress.js` و`assets/profile-state.js`.
- مكتبة «صفحات فضول» مستقلة في `stories/`، مع فهرس وبيانات وقارئ وتقدم محفوظ محليًا. الروابط الموجودة إلى الألعاب والقصص والحلقات والمواد التعليمية لم تُحذف.
- الإحصاءات الظاهرة في الرئيسية تطابق بيانات الألعاب، لكن وصف الصفحة وبيانات المشاركة ما زالت تشير إلى 275 مستوى. كذلك تحمل سبع بطاقات ألعاب أعداد مستويات ونجوم مرئية قديمة مقارنة بالبيانات الفعلية. هذه مشكلة موجودة مسبقًا، ولم تُعدّل في التجربة البصرية؛ يوصى بمراجعة مصدر موحّد للأرقام في تغيير منفصل.
- يستخدم المشروع حزمة اختيارية للتصفح دون إنترنت في `offline-pack.json` مع `sw.js`. أي تعديل للواجهة ينبغي أن يراعي ملفات الحزمة والتخزين المؤقت؛ تشغيل `scripts/build-pwa.py` يعيد كتابة ملفات كثيرة، فلا يُشغّل دون مراجعة أثره.

## قرارات التجربة

- طبقة الأنماط الجديدة `assets/home-manus-experiment.css` محصورة بالصفحة العربية عبر `body.manus-home-review`، وتُحمّل بعد أنماط المشروع الأصلية. يمكن التراجع عنها بحذف رابط ملف الأنماط والصنف، دون تغيير المحركات أو الصفحات الأخرى.
- أضيفت اختصارات واضحة للألعاب والحلقات والقصص وموارد الكبار، كما أضيف رابط القصص إلى قائمة الهاتف؛ واحتُفظ بالأقسام والروابط السابقة جميعًا.
- يستخدم التصميم خطوط المشروع وصوره الموجودة، ويدعم الاتجاه من اليمين إلى اليسار، ومقاسات الهاتف والحاسب، والتنقل باللمس ولوحة المفاتيح وتقليل الحركة.
- أُدرج ملف التنسيق في حزمة الاستخدام دون اتصال ورُفع إصدار الحزمة التجريبي؛ لا يعني ذلك تحديث نسخة Android المثبتة ولا نشر الموقع.
- نُقل رابط تنزيل Android في الرئيسية إلى مكان ثابت داخل شريط الاستكشاف بدل الزر العائم، لمنع حجب المحتوى عند اللمس أو التنقل بلوحة المفاتيح. بقي الرابط نفسه محفوظًا بعلامات المولّد.

## التحقق والمتابعة

من جذر المستودع، شغّل فحوص المشروع الموجودة:

```sh
python3 scripts/verify-v5.py
python3 scripts/verify-seo.py
python3 scripts/verify-learning-presence.py
```

ويمكن تشغيل فحص الواجهة التجريبية مع Node وPlaywright وChromium بعد تثبيتها محليًا:

```sh
node scripts/test-manus-home-review.cjs
# عند استعمال Chromium مثبت على النظام بدلاً من متصفح Playwright:
CHROMIUM_PATH=/usr/bin/chromium node scripts/test-manus-home-review.cjs
# لإضافة اختبار تنزيل الحزمة وإعادة فتح الرئيسية دون اتصال:
TEST_OFFLINE=1 CHROMIUM_PATH=/usr/bin/chromium node scripts/test-manus-home-review.cjs
```

يفحص الاختبار خمسة عروض، روابط الألعاب العشرين وبداية مستوى في كل منها، قائمة الهاتف، استئناف لعبة محفوظة والتنقل في قصة. اختُبرت كذلك إعادة فتح الرئيسية دون اتصال بعد تنزيل الحزمة. لا يغني ذلك عن اختبار جميع المستويات واللغات والأجهزة أو بناء Android وفحص الاستخدام دون اتصال الكامل قبل إصدار فعلي.

## اقتراحات لاحقة خارج نطاق هذه التجربة

1. توحيد الأعداد الظاهرة والبيانات الوصفية مع مصدر الألعاب، وإضافة اختبار يمنع تكرار التضارب.
2. بعد اعتماد أسلوب الرئيسية، تطبيق نظام بصري متسق على مكتبة الألعاب والقصص وصفحات الألعاب تدريجيًا، مع الحفاظ على بيانات التقدم والنسخ الاحتياطي والوصول دون اتصال.
3. إجراء اختبار استخدام مع الأهالي والأطفال، وقياس الأداء والتباين وحجم أهداف اللمس على أجهزة فعلية قبل أي نشر، ثم مراجعة النسختين العربية والإنجليزية وتطبيق Android على حدة.
4. مراجعة زر تحميل التطبيق العائم في بقية الصفحات، والنظر في تحسين الوصول للأقسام البعيدة مع الاحتفاظ بجميع الألعاب. ومراجعة تعليمات «سيارة الحركات» لمواءمتها مع طريقتَي التفاعل باللمس.
